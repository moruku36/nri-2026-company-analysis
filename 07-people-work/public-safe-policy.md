# Public-Safe Policy — 公開版レポートの情報取扱い

このリポジトリは公開を前提とする。

個人向けの示唆を含む場合でも、**公開情報から一般化できる内容だけを記載し、特定個人・顧客・社内業務に紐づく機微情報は扱わない**。

## 記載する情報

- NRI公式IR・ニュースリリース・公開レポート
- 公開された経営陣発言
- 公開された採用・人材戦略情報
- 公開された技術ブログ・イベント資料
- 報道・市場データ・公開口コミを適切な注意書き付きで利用した分析
- 公開情報から一般化した職種別キャリア示唆
- Cloud / Security / PM / Architecture等の一般的なスキル分析

## 記載しない情報

### 個人情報

- 健康・通院・服薬等
- 家族・交際・結婚等
- 住所・住居計画
- 個人資産・口座・保険
- 個別の勤務状況
- 個人評価・昇進状況
- 上司・同僚との個別関係

### 会社・顧客の非公開情報

- 未公表プロジェクト
- 顧客名と案件内容の非公開な組み合わせ
- 社内限定資料
- 社内チャット / メール
- 社内システム構成
- 非公開のセキュリティ設定
- 契約・単価・原価
- 未公表の組織変更
- 内部人事情報
- インシデントの非公開詳細

### 推測で個人・部署を特定できる情報

公開情報と組み合わせることで個人やチームが特定される可能性がある具体的な日付、役割、案件、勤務地等も避ける。

## 個人向け示唆の書き方

> 特定の個人は現在○○部で△△案件を担当しているため、次は××を目指すべき。

OK:

> Cloud / Security / PM系の技術者にとって、AI Platform、AI Governance、Outcome-based Deliveryの組み合わせはNRIの公開戦略と整合性が高い。

## Fact / Interpretationの分離

個人向け章でも、会社が公表した方針と本レポートの解釈を混同しない。

### Fact

例:

- AI高度人材3,000名を2028年度目標としている
- セキュリティ高度人材2,000名を目標としている
- 開発人材の上流シフトを中計に記載している

### Interpretation

例:

- Cloud × AI Platformの価値が上がる可能性が高い
- Coordination-only PMの価値は相対的に低下しやすい

後者は会社の公式な人事評価方針ではない。

## Private notesとの分離

将来、個人的な意思決定のために非公開情報を使う場合は、この公開GitHubリポジトリとは別のPrivate workspaceで管理する。

公開リポジトリ側には、Private側の内容を要約して転記しない。

## Review checklist

コミット前に以下を確認する。

- [ ] 個人の健康情報がない
- [ ] 家族・住所・資産情報がない
- [ ] 社内限定情報がない
- [ ] 顧客機密がない
- [ ] 個人や部署を特定する不要な具体情報がない
- [ ] 公開情報にはURLがある
- [ ] FactとInterpretationを区別している
- [ ] 個人向け示唆は一般化されている

## Principle

> **Public repository = public-source analysis only.**

この原則を今後のCommitでも維持する。
